// end-to-end data flow
1

User connects Phantom wallet on frontend

Wallet pubkey is captured. Frontend checks if a CreditAttestation PDA already exists for this wallet on Solana Devnet.

2

Frontend starts a Vero proof session

The dApp stores the connected wallet in the local verifier and opens the official Vero sign-in page.

3

Plugin opens Vero sign-in — user authenticates with Suomi.fi

Extension intercepts matching Positive Credit Register requests after authentication. Plugin watches for the extract/e-service response.

4

Extension captures the Vero /loans REST response

The extension sees the authenticated response after the user opens Loan information. The user clicks Create proof in the overlay to publish.

5

Frontend POSTs proof + wallet address to verifier server

Verifier checks: server is the Vero e-service host ✓, path includes /loans ✓, debt totals are zero ✓, loan/delay/foreclosure arrays are empty ✓, risk_flags == 0 ✓.

6

Verifier server signs + submits Solana transaction

Calls attest_credit() on the Anchor program. Creates a CreditAttestation PDA seeded by the wallet pubkey. Stores proof hash, notary pubkey, timestamp, 90-day expiry.

7

Frontend shows on-chain attestation + Solana Explorer link

User shares their CreditAttestation PDA address with a DeFi lending protocol. Protocol calls check_attestation() — gets { valid: true, risk_flags: 0, expires_at: ... } — and can continue underwriting.

Solana Account Structure CreditAttestation PDA
// PDA seed: ["credit_attestation", wallet_pubkey]
pub struct CreditAttestation {
    pub wallet:           Pubkey,      // 32 — attested wallet
    pub risk_flags:       u32,         // 4  — proven value (0)
    pub proof_hash:       [u8; 32],    // 32 — SHA-256(raw proof)
    pub notary_pubkey:    [u8; 32],    // 32 — which notary signed
    pub verifier:         Pubkey,      // 32 — verifier server pubkey
    pub attested_at:      i64,         // 8  — TLS session timestamp
    pub expires_at:       i64,         // 8  — +30 days
    pub revoked:          bool,        // 1
    pub bump:             u8,          // 1
}

// A lending protocol verifies eligibility like this:
let [pda, _] = PublicKey.findProgramAddressSync(
    [Buffer.from("credit_attestation"), userWallet.toBuffer()],
    PROGRAM_ID
);
const account = await program.account.creditAttestation.fetch(pda);
assert(account.paymentDefaults === 0 && !account.revoked);
assert(account.expiresAt.toNumber() > Date.now() / 1000);
Selective Disclosure Config plugin handlers
// Only these bytes are revealed in the proof:
handlers: [
    // SENT: reveal request line, hide auth cookies
    { type: "SENT", part: "START_LINE", action: "REVEAL" },
    { type: "SENT", part: "HEADERS",    action: "CONCEAL" }, // ← hides Cookie

    // RECV: reveal status + the Vero fields needed to prove risk_flags == 0
    { type: "RECV", part: "START_LINE", action: "REVEAL" },
    { type: "RECV", part: "HEADERS",    action: "CONCEAL" },
    {
        type: "RECV", part: "BODY", action: "REVEAL_MATCH",
        match: /"creditInformationSummary"\s*:\s*\{[^}]+\}/,
        // plus "loans": [] for the no-loans proof
        // everything else in the JSON body stays concealed
    }
]

// What the verifier sees in the proof's revealed bytes:
// GET /omatieto/api/own-information HTTP/1.1    ← request line
// HTTP/1.1 200 OK                              ← response status
// "loanContractsCount": 0 and "loans": []      ← enough for no-loans proof
// (everything else: ████████████████████)      ← concealed
⚠️
Key implementation notes before going to production:
(1) Vero browser endpoint — the exact private e-service JSON path must be confirmed by inspecting real network traffic after auth. The production lender API is documented as /GetCreditRegisterExtract but requires certificates and legal permission.   (2) TLS compatibility — TLSNotary support depends on the target TLS configuration. Check the Vero host before a live demo.   (3) Notary signature verification — the verifier server's verifyNotarySignature() is stubbed. Implement proper Ed25519 verification with tweetnacl before mainnet.   (4) Anchor discriminator — recompute the discriminator hash in buildAttestCreditData() after program compilation.   (5) Regulatory — using credit bureau data in DeFi crosses into EU financial regulation territory (PSD2, GDPR, MiCA). Get legal advice before production.
